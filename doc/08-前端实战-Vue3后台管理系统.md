## 开头：前端不只是"画界面"

很多人以为前端就是把接口数据摆到页面上。但"演示给客户看"的系统，前端承担着**体验**的重担：看板要会讲故事、演示页要有"AI 感"、监控页要开箱即用。这些都不只是"画界面"。

前端文件地图：

```
frontend/
├── src/
│   ├── main.ts                    # 应用入口（挂载 Element Plus / router）
│   ├── router/index.ts            # 路由 + 登录守卫
│   ├── layout/MainLayout.vue      # 主布局：侧边菜单 + 顶栏（含预警铃铛）
│   ├── views/                     # Login/Dashboard/monitor/demo/camera/violation/warning/log
│   ├── api/                       # 接口封装（auth/violation/camera/log/demo/warning）
│   ├── constants/violations.ts    # 共享常量（勿重复定义！）
│   ├── utils/
│   │   ├── request.ts             # axios 封装（token 拦截器）
│   │   ├── draw.ts                # canvas 检测框叠加（演示页/监控页共用）
│   │   └── download.ts            # blob 下载 + 中文文件名解析
├── vite.config.ts                 # 代理 /api、/images → localhost:8000
├── .env / .env.example            # VITE_MEDIAMTX_BASE
└── package.json
```

## 1. 路由与登录守卫：懒加载 + meta 标题

```typescript
const routes: RouteRecordRaw[] = [
  { path: "/login", name: "Login", component: () => import("@/views/Login.vue") },
  {
    path: "/",
    component: () => import("@/layout/MainLayout.vue"),
    redirect: "/dashboard",
    children: [
      { path: "dashboard", ... meta: { title: "数据看板" } },
      { path: "monitor", ... meta: { title: "实时监控" } },
      { path: "demo", ... meta: { title: "临时演示" } },
      { path: "camera", ... meta: { title: "摄像头管理" } },
      { path: "violation", ... meta: { title: "违规记录" } },
      { path: "warning", ... meta: { title: "预警中心" } },
      { path: "log", ... meta: { title: "安全日志" } },
    ],
  },
];

router.beforeEach((to, _from, next) => {
  const token = localStorage.getItem("token");
  if (to.name !== "Login" && !token) next({ name: "Login" });
  else next();
});
```

三个要点：

1. **懒加载**：`() => import(...)` —— 每个页面独立 chunk，首屏只加载登录页（配合 ECharts 按需引入，打包体积 1.1MB→560KB，这是优化报告 P1-1 的数据）；
2. **`meta.title`**：主布局顶栏显示当前页标题（`{{ $route.meta.title }}`）；
3. **登录守卫**：无 token 一律跳登录页。

## 2. 主布局与预警铃铛（MainLayout.vue）

侧边菜单 7 项，顶栏右侧是**预警铃铛**（阶段四的核心交互）：

```vue
<el-badge :value="unread" :hidden="unread === 0" class="bell">
  <el-button circle @click="router.push('/warning')">
    <el-icon><Bell /></el-icon>
  </el-button>
</el-badge>
```

```typescript
async function pollUnread() {
  const { count } = await getUnreadCount();       // 10s 轮询未读数
  unread.value = count;
  if (count > 0 && count !== lastUnread) {
    ElNotification({ title: "预警提醒", message: `当前有 ${count} 条未读预警事件`, type: "warning" });
  }
  lastUnread = count;
}
onMounted(() => { pollUnread(); bellTimer = window.setInterval(pollUnread, 10000); });
onBeforeUnmount(() => { if (bellTimer) window.clearInterval(bellTimer); });   // 清理定时器！
```

三个工程细节：

1. **`lastUnread` 只在"增加"时弹通知**——避免每次轮询都弹（用户被烦死）；
2. **`onBeforeUnmount` 清理定时器**——否则切页面后还在轮询，内存泄漏 + 多余请求；
3. **轮询 10s 与后端 10 分钟冷却配合**——用户感知"实时"又不打爆接口。

## 3. 共享常量：为什么不重复定义（violations.ts）

```typescript
/** 违规类型 key -> 中文名称（与后端 annotate.py 的 VIOLATION_LABELS 保持一致） */
export const VIOLATION_TYPE_MAP: Record<string, string> = {
  no_helmet: "未戴安全帽",
  no_vest: "未穿安全马甲",
  no_mask: "未戴口罩",
};

/** ppe.pt 违规类（NO-*）—— 检测框标红 */
export const NEGATIVE_CLASSES = new Set(["NO-Hardhat", "NO-Mask", "NO-Safety Vest"]);

/** ppe.pt 合规装备类 —— 检测框标绿 */
export const POSITIVE_CLASSES = new Set(["Hardhat", "Mask", "Safety Vest"]);

export function classColor(clsName: string): string {
  if (NEGATIVE_CLASSES.has(clsName)) return "#f56c6c";   // 红：违规
  if (POSITIVE_CLASSES.has(clsName)) return "#67c23a";   // 绿：合规装备
  return "#409eff";                                      // 蓝：其他目标
}
```

**为什么必须集中？** 这套配色/中文名在**后端 annotate.py、前端 6+ 个页面、原始脚本**都要用。如果每个页面各自写一遍：

- 换模型时（类别名变了）要改 N 处，漏一处就"颜色错乱"；
- 中文名不一致（"未戴安全帽" vs "未戴帽子"）导致界面混乱。

> 🧭 工程纪律：跨页面共享的业务常量必须集中定义（前端 `constants/violations.ts` + 后端 `annotate.py`），页面内不重复定义。这与第 7 篇"换模型 5 处清单"是同一逻辑。

## 4. canvas 检测框叠加（utils/draw.ts）

演示页与监控页**共用**同一份绘制逻辑（前端版的 annotate）：

```typescript
export function drawDetections(canvas, detections, violations, onlyViolations = false) {
  const ctx = canvas.getContext("2d");
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  for (const d of detections) {
    if (onlyViolations && !NEGATIVE_CLASSES.has(d.cls_name)) continue;   // "只看违规"
    let color = "#409eff";
    if (POSITIVE_CLASSES.has(d.cls_name)) color = "#67c23a";
    if (NEGATIVE_CLASSES.has(d.cls_name)) color = "#f56c6c";
    ctx.strokeStyle = color; ctx.lineWidth = 3;
    ctx.strokeRect(x1, y1, w, h);
    // 标签底色 + 文字
    ...
  }
  // 违规横幅（顶部）
  if (violations.length) {
    const text = "⚠ 违规: " + violations.map((v) => VIOLATION_TYPE_MAP[v] || v).join("、");
    ...
  }
}
```

**前后端配色必须一致**：前端 `#f56c6c`（红）↔ 后端 BGR `(0,0,255)`；前端 `#67c23a`（绿）↔ 后端 `(0,255,0)`。客户在演示页看到的红框，与违规记录里的标注图红框，是同一套语言。

> ⚠️ 注意：浏览器 Canvas 用 **RGB 十六进制**，后端 OpenCV 用 **BGR 三元组**（红 = `(0,0,255)`）。跨技术栈"同一配色"要小心通道顺序。

## 5. API 封装层（api/ + utils/request.ts）

每个业务域一个文件（`api/violation.ts`、`api/warning.ts`、`api/camera.ts`...），统一封装：

```typescript
export interface DashboardData {
  total: number; today: number; online_cameras: number;
  trend: TrendPoint[];
  types: { type: string; count: number }[];
  ranking: { name: string; count: number }[];
  location_ranking: { location: string; count: number }[];   // 点位排行（阶段四）
}

export function getDashboard(days = 7) {
  return request.get("/api/logs/dashboard", { params: { days } }) as Promise<DashboardData>;
}
```

**TypeScript 的价值**：接口响应有类型，字段名写错在**编译期**报错（vue-tsc），而不是运行时 undefined。

axios 封装（`utils/request.ts`）第 6 篇讲过：请求拦截器附加 token、响应拦截器统一错误提示 + 401 跳登录。注意超时 `60000`——注释写明"首次演示检测需加载 YOLO 模型（约 10~30s），超时放宽"。

## 6. 核心页面走读

### 6.1 演示页（views/demo/index.vue）—— 全系统最复杂的页面

核心数据流（每 500ms 一帧）：

```typescript
async function detectLoop() {
  const blob = await captureFrame();                    // canvas 截帧 → JPEG
  const res = await detectFrame(blob);                  // POST /api/demo/detect
  drawDetections(canvas, res.detections, res.violations, onlyViolations);  // 叠加
  updateStats(res);                                     // 统计面板（帧数/违规/FPS）
  if (res.snapshot_url) addTimeline(res.snapshot_url);  // 抓拍时间线
  if (running) setTimeout(detectLoop, 500);             // 继续下一帧
}
```

页面能力（对应优化报告 P0-3 / P2-1~4 / P2-6）：

| 能力 | 实现要点 |
|---|---|
| 启动反馈 | 先调 `/api/demo/status` 预检 + 全屏"模型加载中，约 10–30 秒"提示 |
| 灵敏度滑块 | 滑块值作为 `conf` 传给 detect 接口 |
| 只看违规 | `drawDetections(..., onlyViolations=true)` |
| 画质/镜像 | `getUserMedia` 约束 + CSS transform |
| 全屏演示 | Fullscreen API，ESC 退出 |
| 演示统计 | 帧数/违规次数/分类型计数/帧率（EMA 平滑） |
| 抓拍时间线 | 违规抓拍按时间排列，点击看大图 |
| 环境自检 | 一键检查：摄像头权限/后端连通/模型就绪 |

### 6.2 实时监控页（views/monitor/）—— 多路同屏 + AI 叠加

- 播放地址来自环境变量 `VITE_MEDIAMTX_BASE`（`frontend/.env`），flv.js 播放 `{base}/live/{id}.flv`；
- 最多 4 路 2×2 网格（`MonitorCell.vue`），自动轮播每 8s 切换焦点；
- **AI 叠加**：聚焦路每 600ms 调 `/api/demo/detect`（`no_save=true`，只检测不入库），把检测框画在视频上——这就是客户看到的"AI 真的在干活"；
- 离线路显示灰色占位 + "离线"角标。

> 💡 **复用设计**：监控页的 AI 叠加**复用演示链路接口**（demo/detect + no_save=true），没有另写一套检测服务——又一次"复用优先"的工程决策。

### 6.3 数据看板（views/Dashboard.vue）—— ECharts 四图

看板布局（el-row/el-col）：

```
┌──────────────────────────────────────────────┐
│ 工具栏：7/30/90 天切换 + 导出下拉（周报/月报）   │
├────────────────────────┬─────────────────────┤
│ 统计卡（总数/今日/在线）  │                     │
├────────────────────────┴─────────────────────┤
│ 违规趋势折线图（span 14） │ 类型分布饼图(span 10)│
├────────────────────────┬─────────────────────┤
│ 摄像头排行（span 12）    │ 点位排行(span 12)    │
└────────────────────────┴─────────────────────┘
```

关键逻辑：

```typescript
// ECharts 实例生命周期管理
function initCharts() { ... }
function resizeCharts() { charts.forEach(c => c.resize()); }
window.addEventListener("resize", resizeCharts);
onBeforeUnmount(() => { charts.forEach(c => c.dispose()); window.removeEventListener("resize", resizeCharts); });

// 15s 自动刷新 + 新增违规提醒
async function load(showToast = true) {
  const data = await getDashboard(days.value);
  if (showToast && data.total > lastTotal) ElNotification({ title: "新增违规", ... });
  lastTotal = data.total;
  updateCharts(data);
}
setInterval(() => load(), 15000);
```

要点：① **resize/dispose 配对**（否则切页面图表残留、内存泄漏）；② **轮询 + 增量提醒**（总数增长才弹通知）；③ **days 切换**重拉接口（`getDashboard(days)`）。

### 6.4 违规记录页（views/violation/）—— 详情抽屉

- 列表：缩略图 + 类型/摄像头/日期筛选 + 分页；
- 行点击 → 抽屉：大图（**原图/标注图切换** `image_url` / `anno_url`）、el-descriptions 证据信息、**帧内检测明细表格**（解析 `detections`，按类别配色 `classColor`）。

### 6.5 预警中心页（views/warning/）—— 规则 + 事件（阶段四）

上半：**规则表**（名称/摄像头/类型/触发条件/状态）+ 新增/编辑对话框（摄像头与类型下拉均可清空 = "全部"）；
下半：**事件表**（触发时间/摄像头/类型/窗口内次数/已读状态）+ 未读筛选 + 标记已读/全部已读 + 分页。

```typescript
export interface WarningRule {
  id: number; name: string;
  camera_id: number | null; violation_type: string | null;   // null = 全部
  threshold: number; window_minutes: number; enabled: boolean;
}
export interface WarningEvent {
  id: number; camera_id: number; camera_name: string;
  violation_type: string; count: number; triggered_at: string; is_read: boolean;
}
```

表单保存时 `camera_id ?? null` —— **用 null 表达"全部"**，与后端模型（`nullable=True`）语义一致。

## 7. 前端质量验证：没有测试，但有两道关卡

本项目**没有配置测试与 lint**（CLAUDE.md 明说：无 pytest、无 ESLint 脚本），但用两道关卡保证质量：

```bash
npx vue-tsc --noEmit   # ① TypeScript 类型检查（编译期抓字段名/类型错误）
npm run build          # ② Vite 生产构建（打包通过 = 语法/导入/资源全部正确）
```

优化报告里每个功能都注明"`vue-tsc` + `vite build` 通过 ✅"——这就是本项目的"前端验收标准"。

> 💡 如果没配测试框架，至少养成"改完前端跑 vue-tsc + build"的习惯。

## 总结

- **架构**：路由懒加载 + 布局守卫 + API 封装 + 共享常量 + 绘制工具；
- **工程纪律**：共享常量集中（violations.ts）、定时器清理、resize/dispose 配对、复用演示接口（no_save）；
- **核心页面**：演示页（canvas 叠加 + 统计 + 时间线）、监控页（多路同屏 + AI 叠加）、看板（ECharts + 轮询提醒）、违规详情（原图/标注图切换）、预警中心（规则+事件）、日志（筛选+导出）；
- **跨栈细节**：前后端配色（RGB vs BGR）、中文文件名（filename*=UTF-8''）；
- **质量关卡**：vue-tsc + vite build。
