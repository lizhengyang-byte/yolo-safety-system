# 第 10 篇：一个人 + AI，几天搭完一套系统——用 Claude Code 快速开发全流程

> 系列博客第 10 篇。这是全系列最有特色的一篇：本项目的真实开发就是 AI 辅助完成的。这一篇复盘"人机结对开发"的方法论、有效提示词的写法、AI 开发的风险与对策，以及可复用的提示词模板库。

---

## 开头：一个时代的事实

2024 年之后，AI 编程助手（Claude Code / Copilot / Cursor 等）把软件开发效率推进了一个数量级。但很多人只把 AI 当"自动补全"用——**真正的价值在"结对协作"**。

本项目的真实开发过程就是 AI 辅助完成的。它不是"纯 AI 生成"的 demo，而是经历了**需求分析 → 系统搭建 → 产品优化 → 数据驱动**完整生命周期，且每一阶段都有真实的踩坑记录。这就是它当教材的原因：

> **一个人 + AI，几天内做出一套可演示、可部署、有产品感的完整系统**——这是智能建造专业学生在毕业设计/竞赛中最需要的能力。

## 1. 核心方法论：人机结对开发的五步循环

AI 辅助开发不是"让 AI 全包"，而是**人出需求和判断、AI 出实现和效率**的结对协作：

```
① 说需求（人）  →  给 AI 清晰的业务目标 + 约束条件
② 出方案（AI）  →  让 AI 给出技术选型与落点（文件、接口）
③ 审方案（人）  →  人把关：是否满足需求？是否有明显缺陷？
④ 实现+验证（AI） →  代码实现 + 接口实测/构建检查
⑤ 验收复盘（人） →  对照需求逐条验收，把教训写进项目文档（CLAUDE.md）
```

### ① 把需求"喂"给 AI 的正确姿势

**坏提示词**：
> "帮我做个工地安全监测系统。"

**好提示词**（本项目实际用的模式）：
> "为本项目建立一个详细的 doc 文件夹……详细教学本项目是如何进行搭建的……语言风格采用大学教学讲义，面向智能建造专业大学生……生成文档文件要结合代码和项目具体情况进行探讨分析讲解。"

拆解好提示词的要素：

| 要素 | 例子 | 为什么重要 |
|---|---|---|
| **角色/风格** | "语言风格采用大学教学讲义" | AI 输出风格立刻对齐 |
| **受众** | "面向智能建造专业大学生" | 决定深度、术语、例子 |
| **范围** | "详细讲述技术栈、需求文档、产品经理文档、AI 快速搭建" | 防止 AI 跑偏/漏项 |
| **约束** | "结合代码和项目具体情况进行探讨分析讲解" | 绑定真实上下文，防"泛泛而谈" |
| **产出物** | "多个 markdown 文件" | 明确的交付格式 |

> 💡 **核心技巧**：AI 输出质量 = 输入上下文质量。**给上下文、给约束、给验收标准**，而不是一句空话。

### ②③ 审方案：人的价值在于判断

以本项目"阶段四（数据驱动）"为例，AI 先出方案，人需要审这些关键决策：

| AI 提议 | 人需要确认的问题 |
|---|---|
| 新增 `warning_rules` / `warning_events` 两张表 | 表结构合理吗？"空值=全部"语义对吗？ |
| 违规入库后触发预警检查 | 触发时机（commit 前/后）对吗？会影响入库性能吗？ |
| PDF 用 reportlab | 依赖要不要加？版本锁不锁？中文怎么办？ |
| 看板加 days 参数 | 与现有接口兼容吗？前端怎么切换？ |

**人的价值在于判断**：AI 会给出"看起来都对"的方案，但业务语义（空值=全部）、架构约束（双份同步）、部署环境（Windows/Docker 中文字体）这些**项目特有上下文**必须人来把关——这正是 AI 不知道、而 CLAUDE.md 记录下来的东西。

### ④⑤ 验证与复盘：证据不可省

本项目每个阶段的验证方式（没有测试框架，但用"实测 + 构建检查"）：

- 后端：**实跑 uvicorn + 写临时测试脚本**，真实请求走一遍（建规则 → 报违规 → 查事件 → 标已读 → 删规则）；
- 前端：`vue-tsc --noEmit`（类型检查）+ `vite build`（构建检查）；
- 文档：每阶段更新 `CLAUDE.md`——**文档是团队记忆，AI 时代的文档尤其重要**（下次对话 AI 会先读 CLAUDE.md）。

## 2. 完整复盘：本项目四阶段 AI 开发历程

### 阶段 0：从 0 到 1 搭建（合并两个仓库）

- 仓库由两大部分合并：原始 Safety-Detection 脚本 + yolo-safety-system 系统；
- 关键 AI 工作：**适配 ppe.pt 模型**（10 类、direct 模式）——把针对另一种模型的代码、配置、文档全部统一到 ppe.pt 约定；
- 产物：`CLAUDE.md`（项目约定文档，AI 与人的共同记忆）、README 适配说明、配置统一。

> 💡 **阶段 0 的教训**：AI 接手项目的第一件事是**读文档、理约定**（CLAUDE.md / README），而不是直接写代码。本项目把"ppe.pt 适配、双份同步、SQLite 陷阱"全写进 CLAUDE.md——这就是后续阶段 AI 很少犯"方向性错误"的原因。

### 阶段 1~3：产品优化（P0/P1/P2）

提示词（实际）：
> "我更看重客户的实际演示效果、演示体验以及产品功能性上的东西。网络安全方面的东西先暂时放一放……假如你是项目经理、产品经理，只从用户体验和便利性的角度进行项目优化，然后重写这个 markdown 报告"

AI 产出《优化报告.md》（第 3 篇讲过），然后分三阶段实现：

| 阶段 | 内容 | 代表实现 |
|---|---|---|
| 一「先救场」 | P0：标注证据图、监控开箱即用+AI叠加、演示加载提示 | annotate.py、VITE_MEDIAMTX_BASE、模型预热 |
| 二「补齐正式功能」 | P1：看板图表化、详情抽屉、测试连接、实时提醒、筛选分页、导出带图 | /api/logs/dashboard、/api/cameras/test、ECharts |
| 三「打磨演示体验」 | P0-4 + P2 系列 | 多路同屏、统计面板、时间线、全屏、环境自检 |

### 阶段 4：数据驱动（第 9 篇的全部内容）

提示词：
> "推进阶段四（周报/月报、PDF 报告导出、预警阈值）"

这次对话踩了三个大坑（全部记录在案）：

1. **SQLite 时间戳 UTC 陷阱**（预警永不触发 → 排查 → 修复 + 迁移）；
2. **reportlab 4.2 图表重构**（LineChart data API 失效 → 手绘 shapes）；
3. **双份同步疏忽**（改一处忘另一处 → CLAUDE.md 约定 + 代码注释）。

> 🧭 **阶段 4 的意义**：AI 开发同样会踩工程坑，但**排查效率高**（AI 能快速定位时间戳差异、读文档找 API 变化），且**教训能沉淀**（写入 CLAUDE.md 防止复发）。这正是"人机结对"的价值：AI 犯错，人沉淀经验。

## 3. AI 开发风险清单与对策

| 风险 | 本项目实例 | 对策 |
|---|---|---|
| **幻觉**（编造不存在的 API/配置） | reportlab 4.2 的 `LineChart.data`（实际已失效） | 让 AI 查文档/实测；重要 API 先跑通再批量用 |
| **遗忘项目约束** | 只改 backend 的 annotate.py 忘同步 inference | 写进 CLAUDE.md + 文件头注释 + 人验收核对清单 |
| **时间/时区错误** | SQLite CURRENT_TIMESTAMP 存 UTC | 写进 CLAUDE.md"陷阱"章节，AI 每次读 |
| **依赖升级破坏** | reportlab 4.2 图表重构 | 锁版本 + 手绘兜底 |
| **过度自信**（AI 说"全部完成"其实没验证） | — | 每个阶段要求 AI 给出**验证证据**（实测输出/构建日志） |
| **上下文丢失**（长对话后 AI 忘前提） | 修改老代码时用了不存在的变量 | 关键约定写文档；改代码前先 Read 再 Edit |

**通用对策**（本项目实践总结）：

1. **CLAUDE.md 就是"AI 的记忆"**：约定、陷阱、常用命令全写进去，每次会话自动加载；
2. **改代码先 Read 再 Edit**：AI 不能凭记忆改文件，必须先读实际内容（本项目曾因"凭记忆改"引入 NameError）；
3. **每次交付要验证证据**：接口实测输出、构建日志、文件存在性检查；
4. **临时测试脚本用完即删**：验证代码不留垃圾（本项目 `_test_*.py` 全部清理）；
5. **分阶段提交**：每个阶段一个 commit，回滚成本低、历史可追溯。

## 4. 提示词模板库（直接可用）

### 模板 1：需求 → 方案（新功能）

```
[角色] 你是本项目的产品经理+技术负责人。
[项目背景] 这是工地AI安全监测系统（FastAPI + YOLOv8 + Vue3），关键约定：
- 违规判定为 direct 模式（ppe.pt 模型，10类，直接输出 NO-* 违规类）
- inference/ 与 backend/app/detection/ 的 detector/judge/annotate 必须双份同步
- SQLite 时间戳必须用 Python 侧 datetime.now()（本地时间），不能用 server_default
[需求] 我要新增：<功能描述>
[要求] 请给出：1) 涉及文件清单 2) 数据模型/接口设计 3) 分步实现方案 4) 风险点
```

### 模板 2：代码 → 解读（学习/答辩用）

```
请解读 <文件路径> 的这段代码，要求：
- 按执行流程组织，说明每段的职责
- 指出与 <项目约定> 相关的设计（如双份同步、direct 判定）
- 用"为什么这么写"的视角讲解，而不是复述
```

### 模板 3：完成 → 验证（阶段验收）

```
你刚才实现了 <功能>。请按以下清单验证并给出证据：
1. 后端：启动 uvicorn，用 <curl/脚本> 实测 <接口>，贴出响应
2. 前端：运行 vue-tsc --noEmit 与 vite build，贴出结果
3. 文档：更新 CLAUDE.md / README 中受影响的部分
4. 检查双份同步：确认 <文件> 与 <文件> 逐行一致
```

### 模板 4：踩坑 → 沉淀（写进项目文档）

```
我们踩了一个坑：<现象>，根因是 <原因>。
请把这条教训写进 CLAUDE.md 的「重要陷阱」章节，
并检查代码中是否还有 <同类问题> 的其他位置。
```

## 5. 一个人 + AI 能做多少事？（本项目的答案）

本项目从"两个旧仓库合并"到"完整产品功能 + 数据驱动 + 全套讲义"，工作内容包括：

- 后端 30+ 接口（认证/摄像头/违规/日志/演示/预警）
- 前端 8 个页面（看板/监控/演示/摄像头/违规/预警/日志/登录）
- 推理服务（多线程拉流 + 检测 + 判定 + 抓拍 + 上报）
- 4 张表 + schema 演进 + 存量数据迁移
- Excel/PDF 导出（中文文件名、内嵌图片、手绘图表）
- 3 份配置体系（本地/Docker/前端环境变量）
- 完整文档：README、CLAUDE.md、优化报告、本系列博客 11 篇

**核心结论**：AI 不是替代人，而是把"开发效率"放大 5~10 倍，让人把精力放到**需求判断、架构约束、验收验证**上——这正是智能建造专业"懂业务 + 会用工具"的人才定位。

## 总结

- 五步循环：说需求 → 出方案 → 审方案 → 实现验证 → 验收复盘；
- 好提示词 = 角色 + 受众 + 范围 + 约束 + 产出物（**给上下文**！）；
- CLAUDE.md 是 AI 的记忆：约定、陷阱、命令都要写进去；
- 风险与对策：幻觉（验证）、约束遗忘（文档+核对）、依赖升级（锁版本）、时间时区（陷阱清单）；
- 人机分工：人出判断，AI 出效率；验证证据不可省。
